## 🏛️ Security Architecture & Privacy Safeguards

Vyomix is architected with a **Zero-Trust, Local-First** paradigm designed specifically for mission-critical Earth observation data, disaster management corridors, and defense telemetry.

### 1. In-Browser Client-Side Neural Execution (Zero Server Relays)
- All ONNX neural tensor pipelines, adaptive Lee speckle filters, and radiometric calibration routines execute **100% client-side** using `onnxruntime-web` over WebAssembly SIMD and WebGL.
- Satellite raster datasets (GeoTIFF, TIFF, JP2, Sentinel bands) are processed in local browser memory. No raster data is transmitted to unauthorized intermediate proxy relays.

### 2. Zero-Retention Ephemeral Storage Architecture
- Imagery and conversational context reside strictly in the user's local browser memory and sandboxed `IndexedDB` (`localforage`).
- **No telemetry harvesting**: User queries, coordinates, and bounding box coordinates are never sent to centralized telemetry trackers or third-party analytics trackers.

### 3. API Key Protection & Local Key Isolation
- All API credentials (e.g., Gemini API keys, GeoChat Gradio backend URLs, Bhashini credentials) are stored exclusively in the user's browser `localStorage` on the local origin.
- Keys are transmitted directly over encrypted TLS 1.3 to official endpoints and are never logged, proxied, or relayed through Vyomix-owned servers.

### 4. Tamper-Evident Forensic Document Hashing
- Analytical PDF reports generated by the platform embed a deterministic cryptographic **SHA-256 audit seal** and document ID (`VYX-SHA256-...`).
- This ensures that mission dossiers generated for disaster assessment or regulatory land auditing can be verified against unauthorized tampering or retroactive modification.

### 5. Transport Security & Network Isolation
- All external data fetching (Sentinel basemaps, Copernicus data portals, ESRI Wayback archives, translation services) is strictly enforced over **HTTPS / TLS 1.3**.
- Web workers and canvas raster decoders run within sandboxed execution boundaries to prevent cross-origin data exfiltration.

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability, flaw, or data leakage concern in Vyomix, please report it promptly following our **Responsible Disclosure Policy**.

### Disclosure Protocol
- **Maintainer:** Shreyas J ([@SmartKidzee](https://github.com/SmartKidzee))
- **Confidential Channel:** Please submit vulnerability reports via [GitHub Private Security Advisories](https://github.com/SmartKidzee/vyomixsih/security/advisories/new).
- **Advisory Guidelines:** Include steps to reproduce, affected components, and potential impact assessment.

> [!IMPORTANT]
> **Please do not report security vulnerabilities through public GitHub issues or public discussions.** Publicly disclosing vulnerabilities before a patch is available puts defense, research, and disaster relief users at risk.

## 🔍 Security Checklist for Production / Air-Gapped Deployments

For high-security government installations (e.g., ISRO Bhuvan integration, state disaster management rooms):

1. **Self-Hosting Static Assets:**
   - Host all CesiumJS terrain tiles and ONNX model weights (`.wasm` and `.onnx`) from internal intranet servers to maintain air-gapped isolation.
2. **Content Security Policy (CSP):**
   - Implement strict CSP headers disabling `unsafe-eval` and restricting `connect-src` only to internal endpoints and official satellite basemap domains.
3. **Storage Sanitization:**
   - Use the built-in **"Clear Session"** action to purge local IndexedDB caches and volatile canvas memory after high-classification analysis sessions.
